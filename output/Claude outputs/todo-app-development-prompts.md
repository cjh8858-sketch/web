# 할 일 관리 앱 - 5단계 개발 프롬프트

클로드 코드(Claude Code)에서 각 단계별로 실행할 프롬프트입니다. 각 단계를 완료한 후 다음 단계로 진행하세요.

---

## 📋 단계 1: HTML 구조 및 기본 CSS 작성

**목표**: 브라우저에서 바로 실행 가능한 기본 레이아웃 완성

**프롬프트:**

```
순수 HTML/CSS만 사용해서 할 일 관리 앱의 구조를 만들어 줘.

다음 요소를 포함해야 해:
- 페이지 제목: "To-Do Manager"
- 진행률 바: 프로그래스 바와 "0/0" 텍스트 표시
- 입력 섹션: 텍스트 입력 필드 + 카테고리 드롭다운(업무/개인/공부) + 추가 버튼
- 필터 섹션: "전체", "업무", "개인", "공부" 버튼
- 할 일 목록: 아직 비어있어도 됨 (예시 구조만 포함)
- 각 할 일에: 체크박스 + 제목 + 카테고리 라벨 + 수정 버튼 + 삭제 버튼

CSS 디자인:
- 깔끔하고 모던한 스타일
- 색상: 주색 #3498db (파란색), 배경 #f5f5f5
- 여백과 정렬이 명확한 레이아웃
- 다크모드 미지원 (라이트 테마만)
- 폰트: 시스템 기본 폰트 (Segoe UI, -apple-system)

결과물: 단일 HTML 파일 (CSS는 <style> 태그, JS는 아직 없음)
```

**확인 사항:**
- [ ] HTML 파일이 브라우저에서 정상적으로 열리는가?
- [ ] 모든 입력 필드와 버튼이 보이는가?
- [ ] 레이아웃이 깔끔하고 읽기 쉬운가?

## 📋 단계 2: JavaScript 상태 관리 및 기본 기능 구현

**목표**: 데이터 구조 정의 및 할 일 추가/삭제/토글 기능 완성

**프롬프트:**

```
단계 1의 HTML에 JavaScript를 추가해서 기본 기능을 구현해 줘.

구현할 기능:
1. 데이터 구조
   - todos 배열: { id, title, category, completed } 객체로 관리
   - currentFilter: 현재 필터 상태 (전체/업무/개인/공부)

2. 주요 함수
   - addTodo(title, category): 새 할 일 추가 (id는 Date.now() 사용)
   - deleteTodo(id): 할 일 삭제
   - toggleTodo(id): 완료/미완료 상태 토글
   - setFilter(category): 필터 변경
   - render(): 화면 다시 그리기

3. 동작
   - "추가" 버튼: 입력 필드의 텍스트를 todos에 추가
   - 빈 입력은 무시하기
   - 각 할 일의 체크박스: toggleTodo() 호출
   - 삭제 버튼: deleteTodo() 호출 (확인 없음)
   - 필터 버튼: setFilter() 호출 후 화면 갱신
   - 필터된 목록만 화면에 표시하기 (하지만 진행률은 전체 기준)

4. 사용성
   - 입력 후 엔터 키로도 추가 가능
   - 추가 후 입력 필드 초기화
   - 버튼 활성화/비활성화 상태는 아직 구현 안 해도 됨

결과물: 전체 기능은 localStorage 연동 전이지만, 기본 기능이 모두 작동해야 함
```

**확인 사항:**
- [ ] "추가" 버튼으로 할 일이 목록에 나타나는가?
- [ ] 체크박스로 완료 상태가 바뀌고 취소선이 표시되는가?
- [ ] 삭제 버튼으로 할 일이 제거되는가?
- [ ] 필터 버튼으로 카테고리별 필터링이 작동하는가?
- [ ] 콘솔에 에러가 없는가?

## 📋 단계 3: 진행률 계산 및 표시

**목표**: 진행률 바와 백분율이 실시간으로 업데이트되도록 구현

**프롬프트:**

```
단계 2의 JavaScript에 진행률 기능을 추가해 줘.

구현할 기능:
1. updateProgress() 함수
   - 전체 할 일 개수 계산
   - 완료한 할 일 개수 계산
   - 진행률 % 계산: (완료 / 전체) × 100
   - 0으로 나누기 처리: 전체가 0이면 진행률 0%
   - 진행률 바의 width 업데이트
   - 텍스트 업데이트: "40% (4/10)"

2. 진행률 바 스타일
   - 배경색: #e0e0e0 (밝은 회색)
   - 진행 색: #3498db (파란색)
   - 높이: 약 20px
   - 부드러운 모서리 (border-radius)
   - 백분율 텍스트는 바 위에 표시

3. 호출 시점
   - addTodo() 후
   - toggleTodo() 후
   - deleteTodo() 후
   - 필터 변경 후는 안 해도 됨 (필터는 진행률에 영향 없음)

4. 초기 상태
   - 페이지 로드 시 진행률 0% (0/0) 표시
```

**확인 사항:**
- [ ] 할 일을 추가하면 진행률이 0%에서 업데이트되는가? (1개 추가면 0%, 2개이면 0%)
- [ ] 체크박스를 클릭하면 진행률이 실시간으로 변하는가?
- [ ] 완료한 개수와 전체 개수가 정확하게 표시되는가?
- [ ] 진행률 바의 너비가 %에 맞게 변하는가?
- [ ] 모든 할 일을 완료하면 진행률이 100%가 되는가?

## 📋 단계 4: localStorage 연동 - 데이터 지속성

**목표**: 새로고침 후에도 데이터가 유지되도록 구현

**프롬프트:**

```
단계 3의 코드에 localStorage를 연동해서 데이터 저장/복구 기능을 추가해 줘.

구현할 기능:
1. saveTodos() 함수
   - 현재 todos 배열을 JSON으로 변환
   - localStorage에 'todoData' 키로 저장
   - 에러 처리: localStorage 용량 초과 시 콘솔 에러만 출력

2. loadTodos() 함수
   - localStorage에서 'todoData' 가져오기
   - JSON 파싱해서 todos 배열로 복구
   - 데이터가 없으면 빈 배열 []로 초기화
   - 에러 처리: 파싱 실패 시 빈 배열 사용

3. 호출 시점
   - 페이지 로드 시: loadTodos() → render() → updateProgress()
   - addTodo() 후: saveTodos()
   - deleteTodo() 후: saveTodos()
   - toggleTodo() 후: saveTodos()
   - editTodo() 후: saveTodos() (아직 구현 안 해도 됨)

4. 테스트 방법
   - 몇 개의 할 일을 추가하고 일부 완료
   - 페이지 새로고침 (F5)
   - 데이터가 그대로 복구되는지 확인
   - 브라우저 개발자 도구 > Application > localStorage > 'todoData' 확인

결과물: 새로고침 후에도 모든 데이터와 상태가 유지되어야 함
```

**확인 사항:**
- [ ] 할 일 2-3개를 추가한 후 새로고침하면 데이터가 유지되는가?
- [ ] 완료 상태도 그대로 유지되는가?
- [ ] 개발자 도구에서 localStorage에 데이터가 저장되어 있는가?
- [ ] 모든 할 일을 삭제한 후 새로고침하면 빈 상태가 되는가?

## 📋 단계 5: 수정 기능 및 마무리

**목표**: 할 일 수정 기능 완성 및 전체 테스트

**프롬프트:**

```
단계 4의 코드에 할 일 수정 기능을 추가하고 전체를 완성해 줘.

구현할 기능:
1. editTodo(id, newTitle, newCategory) 함수
   - todos 배열에서 해당 id의 항목 찾기
   - title과 category 업데이트
   - saveTodos() 호출해서 저장

2. 수정 UI
   - 각 할 일의 "수정" 버튼 클릭 시
   - 모달 또는 인라인 수정 창 (간단한 방식 선택)
   - 현재 제목과 카테고리를 미리 입력된 상태로 표시
   - "저장", "취소" 버튼 제공

3. 선택사항 (수정 UI 구현 방식)
   - 옵션 A: prompt() 사용 (간단함, 카테고리 선택 불가)
   - 옵션 B: 간단한 모달 창 (조금 더 복잡하지만 나음)
   - 옵션 C: 인라인 수정 (고급)
   → 옵션 B 추천 (사용성과 복잡도 균형)

4. 최종 체크리스트
   - 모든 CRUD 기능 작동 확인
   - localStorage 연동 확인
   - 진행률 실시간 업데이트 확인
   - 필터링 정상 작동 확인
   - 새로고침 후 데이터 유지 확인
   - 콘솔 에러 없음 확인
   - 버튼/입력 필드 반응성 확인

5. 코드 정리
   - 불필요한 console.log() 제거
   - 주석 추가해서 가독성 개선
   - 함수명 명확하게 정의
   - 전역 변수 최소화

결과물: 완전히 작동하는 할 일 관리 앱 (HTML 단일 파일)
```

**최종 확인 사항:**
